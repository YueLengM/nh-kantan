# GTNH 股市机制计划书

版本：2.2（设定讨论稿）  
状态：拆分行情 JSON 与游戏 `.cfg` 设置，并制作离线配置器原型

## 1. 目标

在 GTNH 服务器中加入一个由服务器统一维护的股市系统。玩家拥有独立账户，可以选择“看涨”或“看跌”并投入一定金额。市场价格由独立的有限波动系统产生，不由玩家交易量直接推动，也不依赖现实时间或服务器日期，并且短期走势不应暴露出简单、稳定、可预测的规律。

第一版优先保证：

- 多人服务器中所有玩家看到同一市场状态。
- 账户、持仓、结算和手续费在服务器端完成，客户端只负责展示和提交操作。
- 服务器重启后市场、账户和持仓可以继续运行，不因重启凭空重置。
- 价格变化有明确边界，不能无限上涨或下跌。
- 玩家界面使用“投入保证金”和“杠杆倍数”表达风险；系统在确认前展示名义仓位、开仓手续费、预估强平风险和保证金可能全部损失的提示。

## 2. 当前已确定的设定

以下内容来自当前讨论，后续只在你明确修改时改变：

1. 玩家拥有股市账户。
2. 股市账户使用一种独立货币。
3. 市场币可以按配置与一个或多个 GTNH 任务币物品互转。
4. 市场币和任务币两个兑换方向都收取按比例计算的手续费，比例分别配置。
5. 玩家可以对股票选择“看涨”或“看跌”。
6. 市场价格涨跌不是无限制的。
7. 价格变化不根据玩家交易量直接决定。
8. 价格变化不应形成明显的短期固定规律。

本轮已确认：

9. 市场采用可配置的多标的结构；首版默认只启用一支虚构的 GTNH 综合经济指数。
10. 价格只在服务器运行期间按服务器 tick 推进，停机期间不补算。
11. 玩家用直白的“看涨 / 看跌”参与所选股票的方向交易；杠杆上下限按股票配置。
12. 首版默认指数代表虚构的 GTNH 综合经济指数，不对应现实资产或具体物品。
13. 每支股票都可以独立配置名称、唯一 ID、起始价格、绝对下限和绝对上限；起始价格不再固定为 100。
14. 交易使用保证金和杠杆；强制平仓按实际结算，价格跳变可能使账户余额变为负数并形成债务。
15. 价格每 100 个服务器 tick 更新一次。
16. 价格只设置绝对上下限，不设置固定的单次涨跌幅硬上限。
17. 玩家同时持有的交易数量由配置控制：可以设置每支股票的交易数量上限，也可以设置每名玩家全部股票合计的交易数量上限。
18. 玩家可以随时主动结束交易，并按所选股票的当前价格结算；若保证金风险达到强平条件，系统自动强制平仓。
19. 各支股票完全独立波动，首版不引入股票之间的联动或共享趋势。
20. 账户货币暂称“市场币”，显示名称可配置。
21. 新玩家初始市场币余额可配置，默认值为 0；管理员可以通过指令设置余额。
22. 目前规划的市场币获取途径是与 GTNH 任务币兑换；任务币物品通过 ID / 元数据配置，市场币和每个任务币物品允许双向兑换，两个方向分别配置汇率和百分比手续费。
23. 杠杆按每支股票配置最小值、默认值和最大值；首版示例最大值可设为 100×，但不固定写死。
24. 杠杆控件默认选择 1×，玩家可以在配置范围内调整。
25. 每支股票可配置开仓手续费率，按名义仓位百分比收取并在开仓时扣除；默认建议 `0.055%`，设为 `0` 可关闭。首版不收平仓手续费。每支股票可配置强平阈值，默认 `100%`，即浮亏达到保证金时强平；设为 `0` 时关闭该股票的自动强平。杠杆越高，同样的反向价格变化越快达到该亏损比例。
26. 账户允许出现负余额；负余额表示玩家对市场系统的债务。
27. 还债物品单独使用配置的物品 ID / 元数据和市场币价值，只能用于减少负余额，不能通过该路径增加正的市场币余额。
28. 每支股票的强平亏损比例可配置，默认 `100%`（亏损达到保证金时强平）；设为 `0` 时关闭该股票的自动强平。
29. 行情模式在全局配置中按模式 ID 定义，可供多支股票复用；每支股票配置自己的模式列表，列表项包含模式 ID、选择权重和该模式下每次价格更新时的切换概率。
30. 模式输出类型可配置为变化率或绝对价格。每次进入模式时，系统初始化该模式的计算序号 `t`、模式开始价格、上一次计算价格、上一次实际价格、上一次计算变化率和上一次实际变化率；模式公式可读取这些变量并更新自己的随机状态变量。
31. 模式 JSON 与股票 JSON 只保存行情模式定义和股票价格生成参数。价格更新间隔、玩家订单上限等属于游戏/模组配置，放在 GTNH 的 `.cfg` 文件中，不写入这两份 JSON。

## 3. 建议的初版抽象

### 3.1 市场与标的

市场由多个可配置标的组成。首版配置只放入一支股票，但代码和存档从一开始就使用标的 ID，而不是把“指数”写死在账户或交易结构中。

每支股票至少有以下配置：

- 显示名称和稳定的内部 ID。
- 起始价格。
- 正数绝对下限和绝对上限，且下限必须小于起始价格、起始价格必须小于上限。
- 是否启用交易和展示。
- 独立的价格状态和随机状态。
- 每支股票可用杠杆的最小值、默认值和最大值。

每支股票都有自己的当前价格、历史数据、价格边界和随机状态。玩家交易不会改变任何股票的下一次价格，股票之间默认也不互相影响；以后如有需要，可以额外加入可配置的相关性，但不作为首版规则。

行情模式在全局配置中按稳定 ID 定义一次，例如“平稳”“缓慢上涨”“缓慢下跌”“高波动”；每个模式描述价格变化的倾向和波动程度，不直接指定固定涨跌序列。每支股票再列出自己启用的模式，并为每个模式单独设置选择权重和切换概率，因此模式定义可以复用，而股票的行情组合和停留时间仍可不同。

价格每次更新时，先读取该股票当前模式对应的切换概率。若未切换，沿用当前模式生成本次随机涨跌；若切换，则从该股票模式列表中按权重抽取一个不同于当前模式的新模式，再用新模式生成本次涨跌。权重只决定新模式在候选模式中的相对抽取机会，不要求总和为 100%；切换概率表示每次价格更新时离开当前模式的机会。若某模式切换概率为 0，它会一直持续，直到配置变更或管理员操作；若列表只有一个模式，则不会发生模式切换。

每个模式都要配置输出类型：`changeRate`（变化率）或 `absolutePrice`（绝对价格）。系统提供这些公式上下文变量：`t` 是本模式内的价格计算序号；`startPrice` 是进入模式时的市场价格，在模式运行期间保持不变；`prevCalcPrice` 是上一次公式产生、尚未应用价格上下限的计算价格；`prevPrice` 是上一次应用硬上下限后的实际市场价格；`prevCalcRate` 是相邻两次计算价格之间的变化率；`prevRate` 是相邻两次实际市场价格之间的变化率。模式公式还可以使用该模式声明的内部状态变量，例如随机初始相位，并在每次更新时推进这些状态。

进入任一模式（包括首次初始化和模式切换）时，`t` 从 `1` 开始，`startPrice`、`prevCalcPrice` 和 `prevPrice` 都初始化为当时当前市场价，两个上一次变化率初始化为 `0`。公式读取本轮开始前的上下文并输出结果：变化率模式按 `prevCalcPrice × (1 + output)` 得到本次计算价格；绝对价格模式则把 `output` 作为本次计算价格。然后系统应用股票的硬上下限，得到本次实际价格。`prevCalcRate` 更新为“本次计算价格 / 上一次计算价格 - 1”；`prevRate` 更新为“本次实际价格 / 上一次实际价格 - 1”。保存本次计算价格、实际价格和变化率供下一轮使用，并将 `t` 加 1。模式切换不重置股票当前价，只初始化新模式的上下文和内部状态；绝对价格模式可能造成较大跳变，网页配置器应预览价差、触边情况和长期统计。

行情定义文件分为两份，均采用 JSON：

- `modes.json`：全局可复用的模式 ID、显示名、输出类型、公式和自定义状态变量（含随机初始分布与更新表达式）。
- `stocks.json`：股票 ID、显示名、启用状态、起始价、价格上下限，以及每支股票引用的模式 ID、选择权重和切换概率。

模式表达式使用受限的数学表达式语法，由配置器的安全解析器运行，不直接执行 JavaScript 或任意 Java 代码。第一版格式支持数值、系统变量、自定义状态变量、`+ - * / % ^` 运算、括号、数学函数（包括单参数自然对数 `log(x)` 与双参数任意底数对数 `log(x, base)`；`round(x)` 与 Java `Math.round` 一致，等价于 `floor(x + 0.5)`，中点向正无穷方向取整）和 `random(min, max)`；自定义变量在进入模式时按常量或均匀分布初始化，并用更新表达式逐次更新。未来如需 Java 风格脚本，可在 schema 版本升级后扩展。

价格更新间隔、玩家总订单数、每支股票订单数、杠杆范围、手续费、账户和兑换等游戏规则使用 GTNH 模组 `.cfg` 配置，不进入这两份 JSON。例如：

```text
market.updateIntervalTicks = 100
trading.maxOpenPositionsPerPlayer = 1
trading.instruments.gtnh_index.maxOpenPositionsPerPlayer = 1
trading.instruments.gtnh_index.minLeverage = 1
trading.instruments.gtnh_index.maxLeverage = 100
```

开仓费率按股票分别配置。玩家账户必须同时覆盖保证金和开仓手续费；确认界面分别展示两者。兑换手续费属于独立规则，不受此设置影响。

配置校验必须保证 ID 唯一、价格为正数、下限小于起始价且起始价小于上限，杠杆范围为正整数且最小值不大于最大值，开仓手续费率不小于 0，强平亏损比例不小于 0（0 表示关闭自动强平），还债物品价值为正数。新增股票时从配置的起始价创建自己的市场状态；修改已有股票的名称或边界时不重置当前价格和历史。停用或删除股票前，管理员必须先处理该股票上的所有玩家交易，避免出现无法结算的持仓。行情配置还须保证每支股票至少引用一个已定义模式，模式 ID 存在，权重不小于 0 且总权重大于 0，切换概率在 0 到 1 之间；模式输出类型必须是变化率或绝对价格，公式必须通过表达式校验，变量初始分布必须有效。

开仓前由服务器检查两项限制：玩家当前全部未结束交易数必须低于 `trading.maxOpenPositionsPerPlayer`，且该玩家在所选股票上的未结束交易数必须低于该股票的 `maxOpenPositionsPerPlayer`。任一上限已达到就拒绝开仓，并向玩家说明是该股票名额已满还是总名额已满。并发开仓请求也必须在服务器端串行校验和提交，不能因同时点击而超过上限。

### 3.2 账户

账户至少包含：

- 可用账户货币。
- 账户余额，可为正数、零或负数；负数部分即为债务。
- 当前投入交易、暂不可用的金额。
- 已实现盈亏。
- 未实现盈亏。
- 手续费累计。
- 标的 ID、看涨或看跌方向、投入金额和开仓价格。
- 当前交易数量，以及按股票分组的交易数量索引。
- 债务状态，以及可用于还债的物品配置索引。

市场币账户规则：

- 市场币是模组自己的账户数值，不直接对应物品栏物品。
- 账户显示名称由配置决定，文档和首版默认名称使用“市场币”。
- 新玩家创建账户时使用配置的初始余额，默认是 0。
- 管理员可以通过服务器指令发放、扣除或设置玩家市场币；具体指令名称在实现阶段按 GTNH 模组模板确定。
- 普通玩家不能通过客户端伪造余额、债务或兑换结果，所有余额和债务变化由服务器端原子结算。
- 账户为负余额时，玩家可以进入“还债”页面；还债物品不是普通兑换货币，不能在普通兑换页面兑换成市场币。

账户数据应按玩家 UUID 保存，不依赖玩家当前是否在线。所有余额变化必须在服务器端以一次完整交易操作提交，避免客户端重复提交或重放造成重复结算。

### 3.3 价格引擎

建议对每支股票分别使用“有界随机过程 + 缓慢回归 + 隐藏状态”的组合，而不是纯随机数或固定正弦曲线：

- 价格必须始终处于配置的绝对下限和绝对上限之间；本版不再设置固定的单次涨跌幅硬上限。
- 单次变化幅度由随机状态、波动率状态和边界回归共同决定，不能从简单的固定步长或固定周期推断。
- 价格接近下限或上限时，回归力增强，降低触碰边界后的长期停留。
- 模式公式可配置输出类型：变化率或绝对价格。公式可以读取本模式序号 `t`、固定不变的 `startPrice`，以及分别保留硬限幅前后结果的 `prevCalcPrice` / `prevPrice` 和 `prevCalcRate` / `prevRate`。
- 每个模式可声明内部状态变量和初始随机分布（例如正弦相位在 `0` 到 `2π` 间均匀抽取）；模式每次更新可推进自身状态。首次进入或切换模式时，`t=1`，开始价和两种上一价格都设为当前实际价格，两种上一变化率设为 0；随后每次公式计算完成后更新上一值并递增 `t`。股票当前价不会因模式切换而重置。
- 模式选择与切换：每支股票按自己的模式列表和权重抽取初始模式；每次价格更新按当前模式的切换概率决定是否切换，切换时按权重从其它已启用模式中抽取。模式内价格仍由其公式和随机状态决定。
- 各股票可以复用全局定义的模式，但模式列表、权重和切换概率互相独立；保存当前模式和随机状态，重启后继续原有状态。
- 公式、内部状态和模式切换概率由可视化网页配置器编辑及预览；配置器展示单次轨迹和多次随机模拟统计，帮助发现不完整周期采样造成的上涨/下跌偏差、边界触碰或极端跳变。
- 每支股票使用独立的事件序号、当前模式 ID、模式内部状态和持久化随机状态，不读取现实日期、现实时间或玩家交易量。
- 重启时恢复事件序号、随机状态和当前价格，避免通过重启重新抽取一条不同走势。
- 价格历史只用于展示和审计，不反向参与玩家交易撮合。

当前模式 ID、事件序号和随机状态都需持久化，重启后从保存状态继续，不重新抽取初始模式。本计划将“与服务器时间无关”解释为：价格引擎不读取现实时间、日期或时间戳，只把服务器运行中的 tick 作为推进机会。服务器停机期间不生成价格事件，重启后从停机前的状态继续运行。

### 3.4 面向玩家的看涨 / 看跌操作

建议保留“判断股票方向”的玩法，并使用截图中直观的保证金和杠杆控件；“做多 / 买入”和“做空 / 卖出”可作为按钮文案，并同时提供“看涨 / 看跌”的解释：

- 玩家选择一支股票，输入保证金并选择杠杆，再选择看涨（做多 / 买入）或看跌（做空 / 卖出）。
- 看涨表示所选股票从开仓到结算上涨时盈利；看跌表示所选股票下跌时亏损，反之亦然。
- 玩家投入金额称为“保证金”；玩家从游戏内整数杠杆选项中选择倍数，范围由配置决定，默认最小 1×、最大 100×。例如 100 市场币保证金、10 倍杠杆对应 1000 市场币名义仓位。
- 盈亏按所选股票价格变化比例乘杠杆计算。例如股票从 100 涨到 101，100 市场币保证金、10 倍杠杆的看涨交易毛盈利约为 10 市场币；看跌则约亏损 10。开仓时另扣按名义仓位计算的手续费，平仓不收费。
- 反向波动会更快消耗保证金。系统持续显示风险和预估强平价格/波动幅度；强平比例大于 0 时，浮亏达到“初始保证金 × 配置的强平亏损比例”即自动平仓；设为 0 时不自动强平，玩家仍可主动结束交易。若价格更新跳过强平阈值，系统按检查时的当前价格结算，实际亏损可能超过保证金并使账户余额变为负数。
- 玩家可以主动结束交易，按当时所选股票的价格结算；平仓不收费。价格每次更新后系统检查保证金风险，并在达到强平线时自动结束。
- 交易没有固定到期日，玩家随时可以结束；玩家离线期间持仓仍保留，并随所选股票价格变化。
- 交易开始前显示保证金、杠杆倍数、名义仓位、开仓手续费、总需支付金额、预估强平风险和“保证金可能全部损失”；持有期间持续显示当前盈亏、距离强平线的风险和可能形成的债务。
- 玩家能否继续开新交易由两层配置共同决定：该股票的单股票交易上限，以及玩家全部股票的总交易上限。
- 首版默认值可以设置为每支股票 1 笔、每名玩家总计 1 笔，但这只是配置，不是代码结构限制。
- 第一版不实现挂单、部分平仓、持仓费或追加资金。

基础计算：名义仓位 = 保证金 × 整数杠杆倍数；开仓手续费 = 名义仓位 × 配置费率；未扣费盈亏 = 名义仓位 × 方向符号 × (当前价格 / 开仓价格 - 1)。方向符号在看涨时为正、看跌时为负。强平比例大于 0 时，触发条件为未实现亏损达到“初始保证金 × 配置比例”，设为 0 时关闭自动强平。强平按实际价格结算，不把交易亏损封顶在保证金内；开仓手续费仍是开仓时单独扣除的费用，因此价格跳变时可能出现负余额。实际强平价需要考虑强平缓冲，不能简单等同于“反向波动 1 / 杠杆”。例如 100 市场币保证金、10×、开仓费率 0.055% 时，名义仓位为 1000，开仓费为 0.55，开仓总支出为 100.55 市场币。

这是一个现金结算的保证金方向合约，不要求玩家真的借入或卖出股票。内部记录方向、保证金、杠杆、名义仓位、开仓手续费、开仓价格和强平阈值；界面以“杠杆越高，较小反向波动也可能亏完保证金，极端跳变还可能产生债务”说明风险，并显示手续费是保证金之外的额外成本。

### 3.5 任务币兑换

兑换模块单独于交易模块实现。首版使用可配置的 GTNH 任务币物品，市场币与每个已配置物品双向兑换，至少包含：

- 任务币物品的注册表：物品 ID、元数据/变体、显示名称和是否启用。
- 每个任务币物品的市场币 -> 任务币兑换比例和百分比手续费。
- 每个任务币物品的任务币 -> 市场币兑换比例和百分比手续费。
- 单次兑换上下限、每日或周期限额（如果需要）。
- 兑换的最小单位和舍入规则。

示意配置：

```text
currency.name = "市场币"
currency.initialBalance = 0
exchange.taskCurrency.gtnh_token.itemId = <配置值>
exchange.taskCurrency.gtnh_token.meta = <配置值>
exchange.taskCurrency.gtnh_token.toMarketRate = <配置值>
exchange.taskCurrency.gtnh_token.toMarketFeePercent = <配置值>
exchange.taskCurrency.gtnh_token.fromMarketRate = <配置值>
exchange.taskCurrency.gtnh_token.fromMarketFeePercent = <配置值>
```

初始市场币可以通过管理员指令或兑换获得；是否增加任务奖励、机器产出或其他获取途径，暂不写入首版规则。

建议所有物品映射、比例、手续费、限额和初始余额都进入服务器配置，并在界面中显示名义兑换量、手续费和最终到账数量，避免玩家只看到汇率而忽略手续费。

### 3.6 还债物品

还债物品是独立于任务币兑换的配置类别。每种还债物品至少包含物品 ID、元数据/变体、显示名称、单个物品对应的市场币价值和是否启用。

- 只有账户余额小于 0 时，玩家才能提交还债物品。
- 服务器按“物品数量 × 配置价值”减少债务，使账户余额向 0 移动。
- 还债结算最多把账户恢复到 0；若最后提交的物品价值超过剩余债务，账户仍只归零，超出的价值作废，不能变成正的市场币余额，也不能进入普通兑换余额。
- 还债物品不会因为股票价格变化而改变价值，也不受任务币兑换比例影响。
- 还债操作记录物品扣除量、债务减少量和剩余债务，避免重复提交。

## 4. 需要你确认的关键规则

这些问题会直接决定数据结构和风险模型，建议先确定第一版答案。

### A. 标的数量

1. 已确定市场采用可配置的多标的结构，首版默认启用一支股票。
2. 已确定首版默认股票代表虚构的 GTNH 综合经济指数，不对应现实资产或具体物品。
3. 已确定每支股票可以配置独立的名称、ID、起始价格、绝对下限和绝对上限。
4. 玩家操作需要面向没有股市知识的玩家，界面使用直白的“看涨 / 看跌”和“投入金额”。
5. 已确定各支股票完全独立波动，首版不引入股票之间的联动或共享趋势。

### B. 价格变化的推进方式

1. 已确定使用服务器运行中的 tick 作为推进机会，不读取现实时间和日期。
2. 玩家全部下线时，服务器仍运行则价格继续变化；服务器停机期间不补算价格事件。
3. 已确定价格每 100 个服务器 tick 更新一次，具体间隔仍作为服务器配置项保存。

### C. 涨跌边界

1. 已确定每支股票只限制自己的绝对上下限，不设置固定的单次涨跌幅硬上限。
2. 价格是否允许接近 0？建议设置正数下限，避免零价格导致方向交易结算出现特殊分支。
3. 达到边界时，是软回归、硬截断，还是触发一次市场事件后改变区间？

### D. 看涨 / 看跌的交易规则

1. 已确定玩家在游戏内选择整数杠杆；可用范围由配置决定，默认最小值为 1×、最大值为 100×。
2. 当前建议不收持仓费或借券费，不要求玩家追加保证金；强平比例大于 0 时按配置阈值自动强制平仓，设为 0 时关闭自动强平。
3. 已确定账户允许出现负余额；强平按实际价格结算，价格跳变可能使亏损超过保证金并形成债务。开仓手续费已在开仓时额外扣除，且不计入保证金可用额。
4. 已确定交易数量上限可配置：每支股票有独立上限，每名玩家还有跨所有股票的总上限。首版默认值建议分别为 1 和 1。
5. 已确定交易按所选股票的当前价格开始，玩家可以随时结束；暂不加入挂单和部分平仓。

### E. 交易方式

1. 选择某支股票后，按该股票当前价格立即成交；暂不加入限价单、止损单等订单。
2. 已确定开仓手续费按每支股票配置，按名义仓位百分比收取；默认建议 `0.055%`，设为 `0` 可关闭。首版不收平仓手续费。每支股票可配置强平阈值，默认 `100%`，即浮亏达到保证金时强平；设为 `0` 时关闭该股票的自动强平。杠杆越高，同样的反向价格变化越快达到该亏损比例。
3. 交易是否设置最小保证金和单笔/周期上限？

### F. 任务币兑换

1. 已确定市场币和已配置的任务币物品允许双向兑换，每个物品的两个方向分别配置比例和百分比手续费。
2. 已确定任务币以可配置的物品 ID / 元数据识别，首版配置填入 GTNH 任务币。
3. 已确定兑换比例跟随配置，每个任务币物品独立配置，不随股票价格变化。
4. 已确定手续费按兑换金额收取百分比，两个方向可以使用不同百分比。

### G. 账户生命周期与管理员能力

1. 账户是否永久绑定玩家 UUID，换名后保留？
2. 是否允许管理员发放、扣除、冻结账户货币和强制平仓？
3. 是否需要交易日志、价格历史导出和管理员回滚工具？
4. 世界复制、服务器迁移或多人同时登录时，账户数据以哪个存档为准？

## 5. 分阶段实现计划

### 阶段 0：规则冻结与离线模拟

- 确定首版启用的股票列表、每支股票的起始价格和价格边界、价格单位及更新推进方式。确定模式公式变量、随机分布、输出类型和网页可视化配置器的表达式格式。
- 确定看涨 / 看跌的杠杆盈亏公式、保证金、强平规则、投入上限和手续费规则。
- 用网页配置器和独立模拟器生成并运行长时间价格序列，检查边界、模式持续时间、不同相位采样的方向偏差、分布、短期自相关和极端行情。
- 固化配置项和数据版本号。

交付物：设定文档、价格引擎模拟结果、初版配置表。

### 阶段 1：模组骨架与账户存储

- 建立 GTNH 目标版本的模组工程。
- 实现服务器端账户数据、UUID 绑定、持久化和数据迁移。
- 实现账户货币的加减、冻结、解冻和原子结算接口。

交付物：可以创建账户、查询余额、重启后恢复数据的最小版本。

### 阶段 2：独立市场价格引擎

- 为每支启用的股票实现独立的有界随机价格状态机。
- 持久化当前价格、随机状态、事件序号和必要的历史摘要。
- 加入管理员配置和只读查询接口。
- 完成重启、多人同时读取和长时间模拟测试。

交付物：服务器能产生并保存统一市场价格，但暂不允许真实交易。

### 阶段 3：看涨 / 看跌交易

- 实现选择方向、输入投入金额、开始交易和主动结算。
- 实现盈亏显示、杠杆选择、保证金保护和保证金耗尽时自动强制平仓。
- 按名义仓位计算并扣除配置的开仓手续费，平仓不收手续费。
- 加入杠杆范围、最小保证金和服务器端权限校验。

交付物：玩家可以用测试资金完成完整的看涨 / 看跌交易生命周期。

### 阶段 4：交易边界与风险控制

- 验证看涨和看跌的盈亏方向、投入金额冻结与返还。
- 验证价格跳变和强平结算时可以产生负余额，但不会超过实际结算结果；验证负余额、债务显示和还债物品结算。
- 验证重启和玩家掉线后持仓仍可正确显示和结算。

交付物：在上涨、下跌、剧烈波动、重启和掉线场景下均能正确结算。

### 阶段 5：任务币兑换

- 对接可配置的任务币物品 ID / 元数据，首版填入目标 GTNH 任务币。
- 为每个任务币物品实现独立的双向兑换比例、百分比手续费、限额和舍入规则。
- 实现独立的还债物品配置与还债流程；只有负余额账户可以提交，结算最多归零且不产生余额。
- 记录兑换日志，防止重复提交。

交付物：市场币与已配置任务币物品的双向兑换功能。

### 阶段 6：玩家界面与管理工具

- 玩家界面展示余额、股票列表、所选股票当前价格、简单历史图、方向、投入金额和当前盈亏。
- 提供“看涨”“看跌”“结束交易”和兑换等操作。
- 提供管理员配置、暂停市场、强制平仓和审计查询。

交付物：可在服务器中日常使用的完整 UI 和管理命令。

### 阶段 7：测试与上线检查

- 单元测试：价格边界、随机状态恢复、模式切换时变量初始化、`t` 递增、限幅前后价格和变化率的独立计算、两种模式输出类型、方向盈亏、杠杆盈亏、强平阈值（100%、其他正值和 0 关闭）及越线跳价、负余额、开仓手续费按名义仓位计算、手续费关闭值、还债物品只减债务、货币原子性和舍入。
- 集成测试：多人同时操作、掉线、重启、存档迁移和重复请求。
- 游戏内测试：客户端界面、权限、任务币对象、实际 GTNH 版本兼容性。
- 上线前保留交易日志和数据备份策略。

## 6. 初版建议默认值（待确认）

为了能够尽快进入原型阶段，可以暂时采用以下默认值，之后全部做成配置：

- 首版默认启用一支股票；市场结构支持继续添加股票。
- 账户货币默认显示为“市场币”，名称可配置。
- 新玩家初始市场币默认为 0，初始余额可配置；管理员可以通过指令设置余额。
- 只支持按当前价格即时成交，不做挂单。
- 玩家选“看涨 / 看跌”，投入保证金并选择整数杠杆倍数；杠杆范围由配置决定，默认最小 1×、最大 100×。
- 强平比例默认 100%，浮亏达到初始保证金时触发；设为 0 时关闭自动强平。价格跳变时实际亏损可能超过该笔保证金并形成负余额；开仓手续费另行计入总损失。可用配置的还债物品减少负余额，但不能换成正的市场币余额。
- 交易数量上限进入配置：每支股票上限和玩家总上限分别配置，首版默认值建议为 1 和 1；暂不实现挂单、部分平仓或持仓费。
- 开仓手续费按每支股票配置，按名义仓位百分比收取，默认建议 `0.055%`；可配置为 `0`。首版不收平仓手续费。每支股票可配置强平阈值，默认 `100%`，即浮亏达到保证金时强平；设为 `0` 时关闭该股票的自动强平。杠杆越高，同样的反向价格变化越快达到该亏损比例。兑换手续费按兑换金额百分比收取，两个兑换方向分别配置。
- 账户允许负余额；还债物品按配置价值只能用于减少债务，不能转成账户余额。
- 账户货币使用整数最小单位，所有结算先用整数运算再按规则舍入。
- 价格每 100 个服务器 tick 推进一次，价格引擎不读取现实时间、日期和玩家交易量。
- 每支股票设置自己的正数下限、起始价格和绝对上限，不设置固定的单次涨跌幅硬上限；边界附近使用软回归。
- 价格状态、账户和持仓都保存版本号，后续规则变化通过迁移处理。
- 市场币与每个已配置任务币物品双向兑换，两个方向分别配置汇率、百分比手续费和舍入规则。

## 7. 暂不纳入第一版的内容

- 复杂衍生品、期权和交割合约。
- 依赖外部网络行情的数据源。
- 用玩家交易量直接操纵价格。
- 需要客户端承担可信结算的逻辑。
